# ADEL-WAF

Framework-agnostic, config-file driven **PHP Web Application Firewall** for shared hosting (built for cPanel accounts
without Imunify360). PHP 8.0+, MIT licensed. Uses Redis when available and falls back to files.

- Anomaly-scoring rules (XSS, SQLi, path traversal/LFI, RFI, command injection, scanners, probing, dangerous uploads) with input normalisation (multi-decode, entities, SQL comments, whitespace, case)
- Inspects URI, query, form and JSON bodies, cookies, headers and upload names (not just `$_REQUEST`)
- Per-IP rate limits and bans, allow/deny lists (CIDR), trusted-proxy aware client IP (Cloudflare alias)
- `monitor` mode (log only) so you can tune before blocking; fails **open** on internal errors
- Signed, updatable rule packs; layered local overrides; per-route/param exclusions
- JSON Lines event log, management CLI (`bin/adel-waf`) and versioned JSON Schemas for external tooling
- Offline web-shell scanner (`bin/adel-waf scan`)

> This is defence in depth, not a replacement for patching or a server-level WAF. See [SECURITY.md](SECURITY.md).

## Install (cPanel)

```bash
cd ~ && composer create-project upadrian/adel-waf adel-waf   # or: composer require upadrian/adel-waf
mkdir -p ~/.config/adel-waf && cp adel-waf/config/waf.php ~/.config/adel-waf/waf.php
php adel-waf/bin/adel-waf check-config
```

Load it before every PHP script (pick one):

| Setup | Where |
|---|---|
| PHP-FPM / CloudLinux (most cPanel) | `public_html/.user.ini`: `auto_prepend_file = "/home/USER/adel-waf/prepend.php"` (takes up to ~5 min to apply) |
| MultiPHP INI Editor | cPanel → MultiPHP INI Editor → `auto_prepend_file` |
| Apache `mod_php` / LSAPI | `.htaccess`: `php_value auto_prepend_file "/home/USER/adel-waf/prepend.php"` |
| Inside an app | `\AdelWAF\Integration\Bootstrap::run();` early in your front controller |

Start with `'mode' => 'monitor'`, watch `~/.adel-waf/logs/events.jsonl` (`bin/adel-waf stats`), add exclusions for
false positives, then set `'mode' => 'block'`. State (logs, bans, rule packs) lives in `~/.adel-waf`, outside the web root.

## Configuration

Plain PHP array (or JSON) – see [config/waf.php](config/waf.php) and [schema/config.schema.json](schema/config.schema.json).
Lookup order: `ADEL_WAF_CONFIG` env var → `waf.local.php` next to `prepend.php` → `~/.config/adel-waf/waf.php`;
`config.d/*.json` drop-ins next to the file are merged on top. Only list what you change.

Redis: `storage.driver = auto` tries Redis (ext-redis or Predis, short timeout, 30 s circuit breaker) then files. Use a unique
`storage.prefix` per account on shared Redis.

## CLI

```
bin/adel-waf check-config | status | contract | list | stats
bin/adel-waf ban <ip> [seconds] [reason] | unban <ip>
bin/adel-waf rules:update <dir|url> [--dry-run] | rules:rollback | rules:status
bin/adel-waf scan <dir>
```
Add `--json` for machine output and `--config=FILE` to pick a config.

## Updatable rules

Rules ship as packs (`manifest.json` + files with sha256, optional `min_engine`) and are layered:
bundled pack → downloaded pack in `~/.adel-waf/rules` → your `rules.disable / scores / custom`. `rules:update` verifies the
sha256s and an ed25519 signature (`manifest.sig`, keys in `rules.public_keys`), compile-tests and ReDoS-probes every regex,
then switches atomically; `rules:rollback` restores the previous pack. Run it from cron – it never runs during a web request.
The bundled pack is generated by [tools/build-default-pack.php](tools/build-default-pack.php).

## External admin tool contract (`contract_version` 1)

The core is headless; a separate project can manage it through stable interfaces:

- **Config**: file + `config.d` drop-ins, validated by `check-config` and [schema/config.schema.json](schema/config.schema.json)
- **Events**: [schema/event.schema.json](schema/event.schema.json); JSONL file, optionally also Redis list `{prefix}list:events` (`logging.redis_events`)
- **Bans**: key `{prefix}ban:{ip}` → JSON `{ip, reason, source, created, expires}` with a native TTL (Redis), or via `ban` / `unban` / `list --json`
- **Status**: `status --json`; **Rules**: drop a signed pack and run `rules:update <dir>`
